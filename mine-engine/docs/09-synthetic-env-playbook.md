> 用 **ALE / ALE-Bench / Harbor** 三个坐标，把「怎么造环境、怎么封装题、怎么判分防腐」一次讲清楚。
> 本文是 07（AWM 环境合成）、08（评测手艺）、03（生态全景）的**整理总纲**：那三篇讲细节，这篇讲坐标系。

## 0. 先澄清：三个名字，是三件不同的事

这是最容易搞混的地方（我自己第一版就搞混了）。它们**不是三个竞品 benchmark**，而是三层不同性质的东西：

| | **ALE** | **ALE-Bench** | **Harbor** |
|---|---|---|---|
| 全称 | Agents' Last Exam | ALgorithm Engineering Benchmark | Harbor（Terminal-Bench 2.0 底座） |
| 出处 | UC Berkeley RDI / Dawn Song 组 | Sakana AI × AtCoder | laude-institute |
| 论文 | arXiv:2606.05405（2026-06） | arXiv:2506.09050（NeurIPS'25） | arXiv:2609.04298（Harbor-Index） |
| **性质** | 评测**基准**（一套题） | 评测**基准**（一套题） | 评测**框架**（跑题的插座） |
| 题目 | 1,490 道专家真实任务 | 40 道 AtCoder 启发式竞赛题 | 不管题，只管怎么跑 |
| 回答的问题 | **怎么判分、怎么防污染** | **怎么让分数永不封顶** | **怎么打包成可复现的任务** |

再加上一个不在同一层、但同样关键的：

| | **AWM**（Agent World Model, Snowflake） |
|---|---|
| 性质 | 环境**合成**流水线（造题的方法论） |
| 规模 | 1,000 个全合成环境 / 10,000 任务 |
| 回答的问题 | **怎么批量造出能用的环境** |

### 一句话串起来

```
AWM 造环境 → Harbor 打包成三元组 → ALE 定判分纪律 → ALE-Bench 定分数形态
(怎么生题) (怎么交付) (怎么判才不作弊) (怎么判才不封顶)
```

**我们 AuLE 的位置**：四层我们都有对应物，但成熟度差很远——
- 造环境：✅ 四组件（注入漏洞/变体/验证/判分）已跑通，缺**自我修正循环**和**多样性度量**
- 打包：✅ `run_harbor_export.py` 已能导出三元组，缺 **oracle/dummy 双跑**
- 判分纪律：🔨 ALE 的 gate-and-score 只做了一半（Gate 2「PoC 真跑」还没接进 Level 3）
- 分数形态：❌ **最大的空白**——我们还是二值/准二值（pass@1、F1 匹配），ALE-Bench 的连续分 + 开放式上限我们**完全没做**

## 1. 坐标一 · ALE：判分纪律与防腐

### 1.1 三层难度：不是"更难的题"，是"不同用途的题"

| 层级 | 题数 | 前沿模型通过率 | 用途 | 我们对应 |
|---|---|---|---|---|
| Near-Term | 59 | ~30% | 短期排行榜、快速迭代 | Level 1（Detect） |
| Full-Spectrum | 55 | ~20% | 覆盖每个子领域 | Level 2（Exploit） |
| Last-Exam | 36 | **~2.6%** | 里程碑，长期天花板 | Level 3（端到端审计） |

**关键设计**：Last-Exam 不是"更难的 Near-Term"，而是**大多数模型 0% 通过**的任务。它锚定的是长期研究方向，不是日常调参。

> 最扎心的对照组：**Codex + GPT-5.5 在 Terminal-Bench 上 82%，在 ALE Last-Exam 上 0%。**
> 同一个模型，换个基准，从优等生变零分——说明这两个基准测的根本不是同一种能力。

**我们的差距**（对照这张表）：
- Level 1 现在模型 F1 = 1.0 → **太简单，应该归类为「训练题」而不是「评测题」**
- Level 2 打穿率 50–83% → 接近 Near-Term，还算合理
- Level 3 两个模型满分 → **还没到 Last-Exam 难度**

### 1.2 Gate-and-score：先卡资格，再评质量

```
Gate 1 JSON 能解析吗？不能 → 0 分
Gate 2 写的 PoC 能编译吗？不能 → 利用分 = 0（识别分照算）
Gate 3 PoC 真跑了吗？跑了但 test fail → 利用分 = 0
────── 过了 gate 才评质量 ──────
识别分 recall / 定位分 IoU / 报告分 severity + chaff bug
```

**我们的现状**：四维评分里"利用"维度**只检查 poc 字段非空，没有真跑 Foundry**。Level 2 已经做了（`run_exploit.py`），Level 3 还没接上。这是 ALE 坐标系下我们**最明确的一个欠债**。

### 1.3 七种 artifact 评分模式（ALE 的核心贡献）

ALE 的铁律：**能代码判的，绝不用 LLM 判。必须用 LLM 时，用窄粒度 yes/no probe，不用整体打分。**

| 模式 | 判什么 | 我们用到没 |
|---|---|---|
| Executable | 跑测试集 | ✅ Foundry forge test |
| Behavioral | 系统状态 dump | ✅ 余额变化差分 |
| Structured tabular | 多字段 manifest | ✅ findings JSON 字段匹配 |
| Exact / hashed | flag 字符串 | 🔨 部分 |
| Free-text | rubric 评分 | ❌ 待加 |
| Geometric / Visual | 3D / 截图 | 不适用 |

### 1.4 一条我修正过的判断：LLM-as-judge 不是不能用，是要有锚

我之前因为 ALE 反对 LLM-as-judge，基本把模型判分否定了。**这个判断被 AWM 的对照实验纠正了**：

| 判分方式 | 表现 |
|---|---|
| LLM-only | 会幻觉（编造没发生的失败） |
| code-only | 遇到环境自身缺陷时很脆 |
| **code-augmented** ✅ | **最佳** |

**结论**：问题不在"能不能用模型判"，而在"判的时候有没有代码证据当锚"。
**我们的落地规则**：判定权仍在代码；judge 只允许看**代码产出的证据摘要**（编译输出、测试 diff、状态 dump），**不允许看全量轨迹**。

## 2. 坐标二 · ALE-Bench：让分数永不封顶

**这一节是本次整理最重要的增量。** ALE 解决的是"别作弊"，ALE-Bench 解决的是另一个更根本的问题——**分数会饱和**。

### 2.1 Beyond Pass/Fail：从二值到连续分

ALE-Bench 的立场很直接：现有 coding benchmark 都是短时程 + 正误二判，**现代模型已经饱和了**。它要做的是：

> **长时程 + 分数制**（score-based）的竞赛——目标不是"做对"，而是"持续找到更好的解"。

对照我们自己：我们的 detect 是 F1（准连续），exploit 是 pass/fail（二值），Level 3 是四维加权（准连续）。
**但难度是固定的**——题一旦生成，天花板就定了。这正是 ALE-Bench 要打掉的东西。

### 2.2 开放式上限：真最优解在计算上不可达

ALE-Bench 的题来自 NP-hard 组合优化，**真最优解算不出来**。这意味着：

> 分数**永远有上升空间**，AI 超过人类之后，benchmark 依然有效。

论文原话：*"Future-Proof & Open-Ended: Continuing even after AI surpass human experts."*

**这是 benchmark 腐烂（benchmark rot）的结构性解药**——不是靠"换一批新题"（ALE 的做法，代价是 90% 不敢公开），而是靠**同一道题上分数永远能涨**。

**而我们两条都有**：
- 题能换（注入漏洞引擎 + 固定 seed，可再生）
- 难度能调（雷的数量、chaff 密度、代码混淆度、跨函数距离 —— 连续旋钮）

**这是我们比 ALE-Bench 更强的地方**：它的难度是题目本身固定的，我们是**可调的连续旋钮**。这一点此前没人讲，值得单独成文（见 I11）。

### 2.3 时间轴：给多少时间，涨多少分

ALE-Bench 实测（同一批题，只改时间预算）：

| 时间预算 | 1 小时 | 几小时 | 几天 | 1 周 |
|---|---|---|---|---|
| 分数 | 58.8 | 77.7 | 87.6 | **92.1** |

**这张表就是"长时程推理"的可测量定义。** 对我们有三层意义：
1. **评测必须报时间预算**，否则分数不可比。我们现在 `run_benchmark` 没记 wall-clock。
2. **时间-分数曲线本身是一个指标**：曲线越陡，说明这题"值得多想"；曲线平了，说明题到顶了。
3. 我们的 Level 3 端到端审计天然是长时程任务，**这条轴我们必须占**。

### 2.4 成本轴：贵 30 倍，值不值？

| 方案 | 平均分 | 成本 |
|---|---|---|
| OpenHands | 905（Top 82.8%） | **$3.25 / 题** |
| Self-Refinement（Gemini 2.5 Pro） | 1198（Top 54.1%） | $11.10 / 题 |
| **ALE-Agent** | **1879（Top 6.8%）** | **$100.33 / 题** |

**只报平均分不报成本，是评测报告里最常见的失真。** ALE-Bench 把两个轴一起报，这个习惯我们要学。

我们自己的成本同理：注入漏洞用哪个模型、AI filter 用哪个模型、判分用不用 LLM judge —— 每条都有价签。**成本—质量前沿**（I10）就是这条轴的正式化。

### 2.5 Performance 归一化：把分数放回人类分布里

ALE-Bench 不直接报原始分，而是转换成 **Elo-like Performance**：看这个分数放在真人参赛者里会排第几。

**这条对我们特别有用**：合成题的绝对分（F1 = 0.87）是没有外部意义的。但如果能说"这个分数相当于人类审计师的第 30 百分位"，它就有了。
这也是 **I9 忠实度**的一个实用补丁：**先做相对锚定（人类分布），再做绝对外推**。

### 2.6 污染检查：他们查了，没查出来

ALE-Bench 论文里有一节专门做 **Contamination and Plagiarism Check**，结论是 *"No significant trend was observed"*。

**注意这个报告的诚实性**：查了但没查出问题，照样写进论文。这是评测报告的规范动作。
我们做可再生基准（I1）时，**"我们查了污染，结果如下"这句话本身就是贡献**，不管结论是查到了还是没查到。

### 2.7 我们要从 ALE-Bench 抄的四件事

| # | 抄什么 | 落到哪 | 工作量 |
|---|---|---|---|
| 1 | 连续分代替二值分 | `score_report_v2` 已部分做到，exploit 模式仍是 pass/fail | 中 |
| 2 | 难度连续旋钮（开放式上限） | 注入算子加参数化强度 | 中 |
| 3 | 时间预算 + 时间-分数曲线 | `run_benchmark` 记 wall-clock，`run_env_quality` 加饱和检测 | **小** |
| 4 | 成本轴 + Performance 归一化 | 新模块 `engine/analytics/openended.py` | **小** |

## 3. 坐标三 · Harbor：任务即三元组

### 3.1 三元组

```
task/
├── instruction.md # 给模型看的题面
├── environment/ # Dockerfile + 初始文件（不含答案）
├── solution/ # oracle 解法（仅验证用）
└── tests/ # verifier，ground truth 住在这里
```

**核心纪律**：ground truth **只能**住在 `tests/` 下。我们的 `run_harbor_export.py` 已经守住了这条。

### 3.2 七阶段验证：一个任务不是"写完就完了"

```
1. 贡献者提交（自测 + checklist）
2. CI 自动检查（oracle 解法过 / dummy 解法挂） ← 我们缺这条
3. 专家人工 review
── 合并 ──
4. 强大模型跑一遍，存轨迹
5. 人工审计轨迹
6. 对抗性攻击审计（主动找"作弊"解法）
7. 最终决定（接受 / 打回）
```

| Harbor 阶段 | 我们对应 | 现状 |
|---|---|---|
| 1. 贡献者提交 | 注入漏洞引擎生成 | ✅ |
| 2. **CI：oracle 过 / dummy 挂** | Foundry 差分 | ❌ **缺 dummy 那一半** |
| 3. 专家 review | —— | ❌ |
| 4. 模型跑轨迹 | AI filter + 4 模型 baseline | ✅ |
| 5. 人工审计轨迹 | —— | ❌ |
| 6. 对抗性攻击审计 | AI filter 筛太易题 | 🔨 部分 |
| 7. 最终决定 | 题目进/出数据集 | 🔨 |

**第 2 条的 "dummy 解法必须挂" 是我们最该立刻补的**：它保证了这道题**不是白送的**——一个空答案/占位答案必须得 0 分。这跟 ALE-Bench 反对白送分是同一件事。我们已实现的chaff 题（sample-0004）就是 dummy 的一种形式，但还没系统化。

### 3.3 版本化

Harbor 用 `terminal-bench@4.0` 语义版本；ALE-Bench 有排行榜版本号。
**我们的方案**：数据集按 git commit hash 版本化。

```
datasets/
├── v0.1/ # 7 题（Level 1）
├── v0.2/ # 15 题（+ Level 2 exploit）
└── v0.3/ # 25 题（+ Level 3 多文件）
```

## 4. 环境合成：AWM 五阶段（造环境的方法论）

坐标一、二、三都讲"怎么评测"，这一节讲**怎么把环境造出来**。

| AWM 阶段 | 我们对应 | 现状 |
|---|---|---|
| 1. Scenario synthesis | 注入算子选题 | ✅ |
| 2. Task synthesis | 题面生成 | ✅ |
| 3. Database synthesis | 合约 + harness | ✅ |
| 4. Interface synthesis | findings JSON schema | ✅ |
| 5. **Verification synthesis** | Foundry 差分验证 | ✅ **我们最强的一环** |

**AWM 真正的杀手锏不是五阶段，是「自我修正循环」**：

> 组件生成后**立即执行**，报错就喂回 LLM 重生成，**平均 1.13 次迭代**就能修好，各阶段成功率 > 85%。

**我们现在是"验证失败就丢弃"** —— 白扔一次 LLM 调用。改成喂错误回去修，**半天能改完**（见 I8）。

### 学术定位（中科院自动化所综述 arXiv:2606.12191）

综述把环境合成切成两大流派六条路径，我们属于：

> **符号合成 → 从零合成（from-scratch）**

这是**扩展性最强、难度最高**的一档。综述说这一档的核心难点是"逻辑自洽 + 执行正确"——**恰好被我们的差分验证解决了**。这是我们最硬的学术立足点。

## 5. 总表：三坐标 × 我们现状 × 差距

| 维度 | ALE | ALE-Bench | Harbor | **AuLE 现状** | 差距 |
|---|---|---|---|---|---|
| 难度分层 | 3 层（30%/20%/2.6%） | 无（靠时间轴拉开） | 无 | 3 层（L1/L2/L3） | ✅ 形似，L3 太易 |
| 分数形态 | 代码判，二值为主 | **连续分，开放式** | 二值 test pass | 准二值（F1/加权） | ❌ **最大空白** |
| 难度可调 | 固定 | 固定（题自带） | 固定 | **连续旋钮** | ⭐ 我们更强 |
| Gate | Gate-and-score | 无 | 无 | 只做了一半 | 🔨 L3 欠 Gate 2 |
| 防污染 | 只公开 10% | 查了没查出 | 无 | **可再生，100% 可公开** | ⭐ 我们更强 |
| LLM judge | 强烈反对 | 无 | 无 | 待加 | 🔨 用 code-augmented |
| dummy 检查 | 无 | 无 | oracle 过/dummy 挂 | 只有chaff bug | ❌ 缺 |
| 时间预算 | 无 | **必须报** | 无 | 没记 | ❌ 缺 |
| 成本轴 | 无 | **必须报** | 无 | 没记 | ❌ 缺 |
| 版本化 | 无 | 排行榜版本 | @4.0 | git hash | ✅ |
| 自我修正 | —— | —— | —— | 失败即丢弃 | ❌ 缺 |
| 多样性度量 | —— | —— | —— | 刚加（0.3665） | 🔨 |
| 忠实度 | 专家真实任务 | 真实竞赛题 | 真实任务 | **未测** | ❌ 最大盲区 |

**读这张表的方法**：⭐ 那两行（难度可调、可再生防污染）是我们**结构性优于所有人**的地方，对外叙事必须站在这两行上；❌ 那几行是欠债，按第 6 节的顺序还。

## 7. 一句话总结

- **ALE** 教我们：判分权交给代码，能公开多少题取决于你能不能防污染。
- **ALE-Bench** 教我们：二值分会饱和，连续分 + 开放式上限才不会腐烂；而且**必须报时间和成本**。
- **Harbor** 教我们：任务是三元组，ground truth 只住 tests/，oracle 得过 dummy 得挂。
- **AWM** 教我们：造环境的关键不是生成，是**生成失败后喂错误回去修**。
- **我们独有的两张牌**：难度连续可调 + 题目可再生（100% 公开也不怕被背）。这两条要站到叙事的最前面。
