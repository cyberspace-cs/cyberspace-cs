# 04 · 三条赛道的数据设计（国家审计 / 企业审计 / 审计师）

> 核心判断标准：**一个赛道能不能做，只看一件事——有没有能自动跑的验证器。**
> 有验证器，就能差分证明"雷是我埋的"，就能自动出 ground truth。
> 没有，就只能回到人工标注的老路。

---

## 0. 统一抽象：四组件在各赛道的落地

我们的引擎只有四个零件。换赛道 = 换这四个零件的实现，**编排层一行不改**。

| 组件 | 智能合约（已有） | 国家审计 | 企业审计 | 审计师 |
| --- | --- | --- | --- | --- |
| **Generator**<br>种子程序 | 干净 Solidity 合约 | 合规的预算执行账套 | 真实勾稽的财报+凭证链 | 一份正确完成的工作底稿 |
| **Operator**<br>注入漏洞 | 程序变换（挪行/删校验） | 在账套里插入违规事项 | 在凭证链里插入舞弊分录 | 在底稿里植入错误程序/结论 |
| **Validator**<br>差分证明 | `forge test` 差分 PoC | 勾稽断裂 + 法条命中 | 勾稽断裂 + 红旗指标越界 | rubric 逐条核对 |
| **Scorer**<br>判卷 | recall/precision/F1 | 违规事项召回 + 法条引用准确 | 舞弊识别 + 定位 + 金额误差 | 程序正确性 + 证据链完整度 |

## 1. 赛道一：国家审计（政府审计 / 审计机关）

### 1.1 场景画像

- **甲方**：审计署、省市审计厅/局
- **典型业务**：预算执行审计、专项资金审计、重大政策落实跟踪审计、经济责任审计、自然资源资产离任审计、国有企业审计
- **政策驱动**：浙江 2026"智能审计工程"、山东"加快审计智能体升级"、审计署 2026-06 将"AI 在资源环境审计中的应用研究"列为重点课题；中国审计学会"人工智能时代的审计（2026）"专题收到 596 篇论文、入选 35 篇

### 1.2 "雷"清单（埋什么）

对照审计机关常用的违规问题分类，每一类都是一个可实现的注入算子：

| 算子 | 埋法（种子程序 → 注入漏洞体） | 典型违规表现 |
| --- | --- | --- |
| `虚假列支` | 在支出凭证链中插入一张无对应合同/验收单的发票报销 | 虚列支出套取资金 |
| `截留挪用` | 把 A 专项资金的支出挂到 B 项目账上 | 专项资金被挪作他用 |
| `规避招标` | 把一份 480 万的合同拆成 3 份 160 万 | 化整为零规避公开招标 |
| `超标支出` | 把某笔"三公"经费金额改到标准线以上 | 超标准、超预算支出 |
| `资金滞留` | 把拨付日期向后推迟 N 个月 | 资金闲置沉淀、政策落实不到位 |
| `虚报进度` | 把项目进度填报为 100% 而验收单缺失 | 骗取/套取财政资金 |
| `违规发放` | 在工资表中插入一笔未经审批的津补贴 | 违规发放津补贴奖金 |
| `债务隐匿` | 把一笔融资从表内移到表外主体 | 违规举债、隐性债务 |

### 1.3 验证器怎么证明（这是本赛道的关键设计）

国家审计的验证器是**双闸门**，两条都要过：

```
闸门 A · 资金流勾稽（硬、可计算）
 预算指标数 = 指标下达数 = 资金拨付数 = 实际支出数 = 决算数
 科目平衡：资产 = 负债 + 净资产；借贷平衡
 → 未注入版：全平衡；注入版：至少一处断裂
 
闸门 B · 法规条款命中（半硬、可枚举）
 违规事实 → 匹配《预算法》《政府采购法》《财政违法行为处罚处分条例》等
 → 未注入版：零命中；注入版：命中 ≥1 条，且命中条款与埋的算子一一对应
```

**差分定义**：健康账套跑验证器 = 全绿；注入漏洞账套跑验证器 = 恰好命中预期的那一条（不多不少）。
"多命中"说明注入漏洞动作不干净（副作用），"没命中"说明这个雷没埋实，都要丢弃。

### 1.4 数据从哪来

| 来源 | 用途 | 敏感性 |
| --- | --- | --- |
| 审计署《审计结果公告》（公开） | 违规问题**类型与表述**的语料，用于构造算子 | 低 |
| 部门预算/决算公开数据 | 账套结构与金额分布的**先验** | 低 |
| 政府采购公告 | 招投标违规模式 | 低 |
| 审计常用法规库（公开法条） | 闸门 B 的规则来源 | 低 |
| **真实审计底稿** | **不可用**，机密 | 高 → 走差分隐私先验 |

**⚠️ 合规红线**：绝不直接把真实审计数据做成公开数据集。
正确做法是照抄 FinancialAuditBench 的路子：
**从真实数据中只提取"差分隐私聚合统计"**（如：某类违规的平均金额分布、账套文件数量分布），
用它作为合成器的先验参数，产出的账套**全部是合成的**。

### 1.5 MVP：第一版做成什么样

> **GovAudit-Mini**：1 个合成部门（教育局）× 1 个年度 × 3 类算子
> （虚假列支 / 规避招标 / 资金滞留）× 每个算子 10 个 seed = **30 题 + 10 个chaff bug**
>
> 输入给 Agent：一个目录（预算表、拨付流水、凭证、合同、验收单，共 30–60 个文件）
> 要求输出：违规问题清单（事项 / 金额 / 违反条款 / 证据文件名）
> 判卷：召回率 + 条款引用准确率 + 金额相对误差

## 2. 赛道二：企业审计（内部审计 / 舞弊 / 内控）

### 2.1 场景画像

- **甲方**：企业内审部、风控、监事会；也可服务会计师事务所的舞弊风险评估
- **理论依据**：舞弊三角（压力 / 机会 / 合理化）；COSO 内控框架
- **已有对标**：AuditFraudBench（SEC AAER，任务2 最好仅 24.5%）、FinAuditing（XBRL 1102 例）、CI-FSFD

### 2.2 "雷"清单

| 算子 | 埋法 | 判定信号 |
| --- | --- | --- |
| `收入提前确认` | 把 12 月的发货单日期改到 12 月，但签收单是次年 1 月 | 收入确认早于风险报酬转移 |
| `费用资本化` | 把管理费用重分类到"在建工程" | 利润虚增 + 资产虚增 |
| `少提减值` | 把应收账款坏账准备计提比例从 5% 调到 1% | 利润虚增 |
| `存货虚增` | 账面存货数量 ≠ 盘点表数量 | 账实不符 |
| `关联交易非关联化` | 通过一家无关联的过桥公司转手销售 | 交易实质被掩盖 |
| `循环交易` | A→B→C→A 走一圈，收入虚增但无真实现金流 | 收入与经营现金流背离 |
| `不相容职务未分离` | 让同一人同时拥有"申请"和"审批"权限 | 内控缺陷 |
| `审批链断裂` | 删除一笔大额付款的二级审批记录 | 内控缺陷 |

### 2.3 验证器（本赛道的优势：全可计算）

```
闸门 A · 三表勾稽（最硬）
 资产负债表平衡；现金流量表期末 = 货币资金科目
 净利润 → 经营性现金流的调节表对得上
 收入 - 成本 - 费用 = 利润（跨表一致）
 
闸门 B · 凭证链完整性
 每一笔收入：合同 → 发货单 → 签收单 → 发票 → 回款，五单齐全且日期单调
 → 注入漏洞后必然缺一单或日期倒挂
 
闸门 C · 红旗指标越界
 Beneish M-Score、Altman Z-Score、应收账款周转天数突变、
 收入增长 vs 经营现金流增长背离度、毛利率异常偏离行业
 → 未注入版：指标在正常区间；注入版：越界
```

**为什么这条赛道最容易做**：闸门 A 和 B **全是确定性算术**，
跟合约赛道的"编译器 + 测试"一样硬。难度比国家审计低，比审计师赛道低得多。

### 2.4 数据从哪来

| 来源 | 说明 |
| --- | --- |
| 上市公司公开财报 + XBRL | 结构、科目、真实金额分布（低敏感） |
| SEC AAER / 证监会行政处罚决定 | **真实舞弊手法**的标注语料（这是金矿：每一份处罚书都写清了"怎么造的假"） |
| 行业财务比率（Wind/CSMAR 口径） | 红旗指标的基准区间 |
| 企业真实账套 | 不可用（机密）→ 合成 |

**⚠️ 与 AuditFraudBench 的差异化**：他们用真实处罚案例做"给定材料判断"，
我们做"合成账套 + 主动注入漏洞 + 差分证明"。**他们是静态题库，我们是引擎。**

### 2.5 MVP

> **CorpAudit-Mini**：合成制造业公司 × 1 个会计年度 × 4 类算子
> （收入提前确认 / 费用资本化 / 少提减值 / 循环交易）× 每算子 8 seed = **32 题 + 8 chaff bug**
> 材料：总账 + 明细账 + 凭证附件 + 合同 + 银行流水（约 40 文件）
> 判卷：舞弊识别 recall + 手法分类准确率 + 金额估计相对误差 + chaff bug误报率

## 3. 赛道三：审计师（CPA / 事务所 / 工作底稿）

### 3.1 场景画像

- **甲方**：会计师事务所、质量控制复核合伙人、CPA 培训机构
- **标杆**：FinancialAuditBench（90 任务，review 设定占一半）——**直接对标的就在这里**
- **行业痛点**（Tellen 2026 报告）：87% 审计从业者认为"会计准则知识"是 AI 最重要的能力，
 但只有 **38%** 放心让 AI 做"最终签署"。

### 3.2 "雷"清单（在底稿里埋，不在账套里埋）

这条赛道的"雷"不是舞弊本身，而是**审计工作本身的错误**：

| 算子 | 埋法 | 对应失职 |
| --- | --- | --- |
| `程序遗漏` | 删掉底稿中对某一高风险认定的实质性程序 | 应做未做 |
| `样本不足` | 把抽样规模从 60 改成 6 | 抽样风险失控 |
| `证据断链` | 把结论所引用的支持性文件从索引中移除 | 结论无支撑 |
| `结论与证据矛盾` | 证据显示存在差异，但结论写"未发现异常" | 职业怀疑缺失 |
| `计算错误` | 把重新计算（recomputation）的结果改错 | 机械准确性缺失 |
| `日期倒挂` | 把审计报告日改到现场工作结束日之前 | 程序时序违规 |
| `擅自变更程序` | 未经批准把函证改为替代程序 | 程序变更未审批 |

### 3.3 验证器（本赛道最难：判卷需要 rubric）

```
闸门 A · 四段链可追溯（可自动）
 风险 → 程序 → 证据 → 结论
 检查每一段是否存在、是否指向一致
 → 注入漏洞后链条必然断裂或自相矛盾
 
闸门 B · 持牌审计师 rubric（半自动）
 每个任务附一份 checklist：应执行的程序 / 应获取的证据 / 应有的结论
 → 由持牌 CPA 设计，可复用（一次设计，N 个 seed 复用）
 
闸门 C · 复核设定（直接抄 FinancialAuditBench）
 completion：给空白底稿，要求做完
 review： 给"已完成"的底稿，要求挑错 ← 这个更妙，成本更低、区分度更高
```

**成本提示**：闸门 B 需要持牌审计师投入，是三条赛道里专家成本最高的
（FinancialAuditBench 用了 1100+ 小时）。
**缓解办法**：rubric 按"任务类型"复用——设计一个"收入截止性测试"的 rubric，
可以用在 20 个不同 seed 的底稿上。专家投入是**一次性**的，不像题目那样需要反复投入。

### 3.4 数据从哪来

| 来源 | 说明 |
| --- | --- |
| 审计准则（中国注册会计师审计准则 / ISA） | 程序要求的形式化来源 |
| 事务所公开的底稿模板 | 结构设计 |
| FinancialAuditBench（MIT 开源） | **可直接参考其 rubric 结构与合成框架** |
| 真实工作底稿 | 不可用（保密 + 职业道德） |

### 3.5 MVP

> **CPAAudit-Mini**：合成服务业公司 × 3 个科目（收入 / 存货 / 银行存款）
> × 5 类算子 × 每算子 6 seed = **30 题**，其中一半设成 review 模式
> 判卷：程序正确性 + 证据链完整度 + 结论一致性 + chaff bug误报

## 4. 横向比较：三条赛道怎么排序

| 维度 | 企业审计 | 国家审计 | 审计师 |
| --- | --- | --- | --- |
| **验证器硬度** | ⭐⭐⭐ 全可计算 | ⭐⭐ 勾稽硬 + 法条半硬 | ⭐ 需 rubric（半自动） |
| **专家依赖度** | 低（手法有公开案例） | 中（需懂财政违规口径） | 高（需持牌 CPA） |
| **数据可得性** | 高（财报/XBRL/处罚书公开） | 中（公告公开，底稿机密） | 低（底稿保密） |
| **甲方明确度** | 中 | **高**（审计署有政策驱动） | 中 |
| **竞争密度** | 高（已有 3 个 benchmark） | **极低（几乎空白）** | 中（有 1 个强对标） |
| **落地速度** | 快（算术验证器） | 中 | 慢 |

### 建议的资源分配

```
第一优先：企业审计 ← 验证器最硬、数据最公开、做得最快，用来验证"四组件抽象真的跨赛道"
第二优先：国家审计 ← 竞争空白 + 政策驱动 + 甲方明确，最容易出独家成果
第三优先：审计师 ← 专家成本最高，等前两条跑通后再用同一套 rubric 机制切入
```

**但叙事上要反过来讲**：对外先讲"国家审计"这条独家赛道（没人做过、有甲方），
工程上先做"企业审计"（最快能证明抽象通用）。

## 5. 三条赛道共用的三个工程件

无论哪条赛道，这三件事都要做一遍，且**可以复用**：

1. **差分验证器接口**（`IssueValidator` 子类）
 统一签名：`validate(clean_artifact, planted_artifact, ground_truth) -> (ok, log)`
 只要能实现这个，赛道就能接进来。

2. **AI Filter**（已有，直接复用）
 换赛道只需换 prompt。判断标准不变：筛选模型全对 = trivial，有错 = differentiating。

3. **Harbor 导出器**（M7 新建）
 把任意赛道的样本导出成 `instruction.md + environment/ + tests/verifier` 三元组，
 立刻能被 Harbor 跑、能被别人复现、能进榜单。

**这三件做完，"一套引擎三条赛道"就不再是 PPT，而是可运行的事实。**
