## 2. 最严重的一条：gap 的"non-trivial"检验没过

skill 的 `gap-analysis.md` Step 3 要求 gap 通过四项检验，第三项是：

> **Non-trivial**：现有 benchmark 无法被**廉价扩展**覆盖（"加几条样本"不够）

我们目前的论证是"测 verifier 需要昂贵 oracle，FinancialAuditBench 实测 1,100 专家小时"。

**反驳只需一句话**：行业实践建议明确写着
> "Build a small audit set — 200–500 (gold, model-answer) pairs sampled from real rollouts and **labelled by hand**"

也就是说 —— 200–500 条手工标注**就能测出 FNR/FPR**。这是"加几条样本"，不是"不可扩展"。

**这意味着**：gap 不是一个**结构性**缺口，而是一个**成本**缺口。
按 skill 的三种 gap pattern 归类：
- Pattern A 维度盲区？—— 部分符合（没人测判分器质量这个维度）
- Pattern B 假设违反？—— **符合且更强**：领域默认"verifier 已在规模使用，所以它是够用的"，
  而 S1 证明这个默认假设在审计域不成立
- Pattern C 粒度不匹配？—— 符合（单层 FNR 会掩盖归因层失败）

**但诚实的后果是**：审稿人会说"那你为什么不直接标 200 条？"
我们唯一站得住的回答是**规模**而不是**可能性**：

| 论据 | 状态 |
|---|---|
| 标200 条能测出 FNR（一次性） | ✅ 承认，这是真的 |
| 但只能测**一个** verifier 的**一个**分布 | ✅ 成立 |
| 我们是**连续**参数化难度旋钮（雷数/跨函数距离/诱饵密度/混淆度） | ✅ 这是真差异，能回答"在哪个难度上失效" |
| 且**边际成本≈0**：10 题→1000 题，单题恒定 0.35 ms | ✅ 实测支持 |
| ⇒ 手工标注做不出**曲线**，只能做**一个点** | ✅ 这是最强论据 |

**建议改写 gap 陈述**（skill Step 4 的模板）：
> Existing verifier studies focus on **whether a verifier can be built**,
> operating under the assumption that **a verifier being widely used is evidence of being adequate**.
> However, in audit/finance/governance domains,
> **verifier error is unmeasured because the reference oracle is assumed unobtainable** —
> and the field's own remedy (hand-labelling 200–500 pairs) yields **exactly one point**,
> not the **error-vs-difficulty curve** that audit tasks require.
> This creates a blind spot: **we cannot tell whether a verifier fails uniformly
> or only past a difficulty threshold** — meaning a verifier can pass a small audit
> and still collapse on a harder distribution.

这段话把"贵"换成了"只能得一个点"，从成本辩护升级为**能力辩护**。

## 3. Construction Pipeline 审计

范式选型 ✅ 正确。对照 `construction-pipeline.md` 的五阶段表：

| 阶段 | 我们的实现 | QC 闸门 | 审计 |
|---|---|---|---|
| 1 Source Selection | 无外部语料，全程序化生成 | — | ✅ 但也意味着**没有真实世界分布**，见下|
| 2 Seed Generation | `make_seed_ledger(seed)`，200 份 × 4 期 | 四oracle 自平 | ✅ 3,200/3,200 |
| 3 Enrichment | 4 种 `FRAUD_OPS` 注入 | DIC 认证（预期项出现 + 无意外项） | ✅ 800/800 |
| 4 Quality Control | 自检 62/62 + 回归 9/9 + smoke 19/19 | 自动化 sanity check | ⚠️ **无人工抽检** |
| 5 Splitting | 无（不做训练/测试划分） | — | ➖ N/A |

**QC 策略对照 skill 要求的 ≥3 种**：

| skill 要求 | 我们有吗 |
|---|---|
| Inter-Annotator Agreement | ➖ N/A（零人工标注，这正是主张） |
| Expert Spot-Check ≥10% | ❌ **缺**（S5 的审计师盲审就是这一项，尚未做） |
| Adversarial Validation | ❌ 缺 |
| Automated Sanity Checks | ✅ 有（且很强） |
| Pilot Study | ✅ 有（先跑 pilot 再全量） |
| LLM Cross-Validation | ⚠️ 部分（S1 用两个模型，但测的是被审对象不是构造数据） |

**Critical 缺口：没有任何人工验证过我们的账套"像真的"。**
seed ledger 是程序化生成的，注入的舞弊是算子写的。审稿人一定会问：
> "你们的账是真的吗？还是一个玩具？"

这个问题目前**无法回答**。而它恰恰是我们最强的护城河（真账 + 真注入 =
外部有效性的天然对照）。S5 审计师盲审从"nice to have"升级为 **Critical**。

对照 `experiments.md`：

| 要求 | 现状 | 严重度 |

| ≥10–15 模型 | **2**（deepseek-flash / v4-pro） | 🔴 Critical |
| 覆盖 4 轴（开源/闭源 · 规模 · 架构 · 专精） | 只覆盖"闭源·同厂商·两个规模" | 🔴 Critical |

| Category Breakdown | ✅ 有（逐手法 FNR） | ✅ |
| Difficulty Gradient | ⚠️ 旋钮调过，但未在 S1 用 | 🟡 Major |
| Error Taxonomy | ✅ 强（检测层/归因层分离是原创） | ✅ |
| Human vs. Model | ❌ 缺（S5） | 🔴 Critical |
| Case Studies 2–4 | 有 1 个（offbook 100% 漏判） | 🟡 Major |
| *Finding X* 句式 | **完全没写** | 🟡 Major |
| 重复 ≥3 次报 mean±std | ✅ 有（repeat=3 + 分歧率） | ✅ |

**好消息**：分层FNR 与"结构性不可见"是**真正的 capability boundary 发现**，
符合 skill 对 Finding 的要求（surprising + specific + actionable）。
现在要做的只是把它写成 lemma 句式。

**必须补的 Finding 候选**（数据已支持，只是没写成句子）：

- **Finding 1.** 判分器的失效**不随能力单调改善**：更强模型把检测层 FNR 从 0.494 压到 0.070，
  归因层 FNR 却从 0.012 升到 0.333，误报从 0.000 升到 0.800。
  ⇒ 换更强的 judge 不买归因能力。
- **Finding 2.** **54.6% 的报警被模型自己的理由否定**（`"折旧正常，无异常"` 却填 `true`）。
  ⇒ 正确信号已在输出里被布尔字段丢弃，这是可被极低成本回收的。
- **Finding 3.** 朴素会计恒等式对 4 种舞弊**全部不可见**（`o_equation` 不在任何破坏集里），
  调整容差无法恢复。
  ⇒ verifier 的失败是**结构性的**，不是阈值问题。
- **Finding 4.** 误报率为 0 时，漏判率升到 100% **也不翻转**训练方向；
  真正危险的是系统性误报。
  ⇒ 社区"降 FNR 就安全"的直觉是错的。
- **Finding 5.** 漏判→1 且误报=0 时，66–100% 的 rollout 组 σ=0，
  训练**无报错停摆**。
  ⇒ 第三种失效形态：不是训坏，是训不动。

这五条如果能写进论文，比再加10 个模型更有价值—— 但**仍需补模型数**，
否则 Finding 1 会被质疑是单对模型的偶然。

## 7. 一条方法论收获（与本项目 S1 教训同源）

skill 的 `gap-analysis.md` 要求 gap 过四项检验，**其中"non-trivial"这一项
会自动杀死大多数 gap 陈述**——因为大家习惯用"贵"当理由，而"贵"是**可被资本解决的**。

我们这次的教训与 S1 一模一样：**台子的问题会伪装成结论**。
S1 是"题面歧义伪装成模型能力"，这次是"成本叙事伪装成结构性缺口"。

> **写 gap 陈述时，必须把"我们没能力做"和"社区不愿做"区分开。
> 只有后者才是护城河。**
