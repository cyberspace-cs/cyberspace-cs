# 02 · 研究演进脉络（从零讲起）

> 假设你完全没接触过这个领域。本文用**"怎么考一个 AI 审计师"**这一条线，
> 把整个领域 6 年的演化讲清楚，并指出我们站在哪一格。

---

## 0. 先建立一个心智模型：这就是一场考试

评价一个 AI 会不会审计，本质就是**给它出一场考试**。
一场考试只有三个零件：

```
 题目（给 AI 看什么）
 ↓
 AI 作答
 ↓
 判卷（怎么算它对）
```

领域里所有的进步，全是围绕这三件事做的：

- **题目**从哪来？（人写？爬真实事故？机器生成？）
- **判卷**怎么判？（人看？对答案？跑测试？）
- 关键是：**这场考试，AI 能不能作弊？**

下面所有的演化，你都能用"这场考试作弊难度大不大"来检验。

---

## 第 0 代：人出题，人判卷（～2020）

**长什么样**：审计竞赛（Code4rena）、CTF、事务所内部培训题库。
人类专家出题，人类专家判卷。

**优点**：质量极高，题目都是真问题。
**致命缺点**：**不可扩展**。出一套题要几个专家几周，考完一次这套题就废了。

> 类比：科举考试，主考官亲自出题阅卷。一年考一次，一次几十人。

---

## 第 1 代：静态数据集 + 标准答案（2018–2023）

**长什么样**：把已知有漏洞的代码收集起来，标注漏洞类型，做成数据集。
代表：SWC Registry、SmartBugs、Slither 的检测用例集。

**进步**：题目可复用，能自动判卷（答案就在标注里）。

**致命缺点**：**答案是死的，AI 会背**。
一个漏洞样本（比如 The DAO 重入攻击）在网上被写了几万篇文章，
模型训练时早就见过，考试时它是"回忆"而不是"推理"。

> 类比：高考真题被汇编成《五年高考三年模拟》，考生把答案背下来了。
> 分数很高，不代表会做题。

**这个"背答案"问题，学术名叫 contamination（数据污染）**。
它是整个领域至今最大的敌人，后面所有的演化都在跟它打。

---

## 第 2 代：让 LLM 来判（2023–2024）

**长什么样**：给模型一段代码问"有什么问题？"，让 GPT-4 当裁判打分。

**进步**：能评以前没法自动评的东西（报告写得专不专业、建议合不合理）。

**致命缺点**：**判卷标准主观**。
模型报告写得"看起来很专业"就能拿高分，至于它说的漏洞是不是真的、能不能被利用，没人管。
更糟的是裁判自己也是 LLM，会有"自己人偏向自己人"的问题。

> 类比：作文评分。字迹工整、引经据典就能拿高分，观点对错没人查。

---

## 第 3 代：可执行验证的 Agent 评测（2024–2026）⭐ 行业现在的主流

**核心转变**：**不看你说了什么，看你能不能做到。**

不再是"请指出漏洞"，而是：

```
给你一个沙箱（一台干净电脑）
 → 你随便折腾：读代码、改代码、跑测试、写攻击脚本
 → 最后看：漏洞修好了吗？/ 钱真的被转走了吗？
```

**代表工作**：

| 名字 | 干什么 | 意义 |
| --- | --- | --- |
| **SWE-bench** | 给真实 GitHub issue，让 Agent 改代码，跑单元测试判对错 | 开了"跑测试才算数"的头 |
| **Terminal-Bench** | 真实终端环境里的长时任务 | 把"沙箱"标准化 |
| **Harbor** | Terminal-Bench 团队做的**评测执行器** | 定义任务三元组，正在成为行业标准 |
| **EVMbench**（OpenAI × Paradigm, 2026） | 合约审计三模式：**detect（找）/ patch（修）/ exploit（打穿）** | 本赛道最强标杆 |

### Harbor 的三元组（必须记住，我们会用到）

```
一个任务 = instruction.md + sandbox + verifier
 (给 AI 的题) (一台电脑) (判卷程序)
```

简单到刻意简陋，正因为简单，它才可能成为标准。
**我们要做的事之一，就是让我们的题能导出成这个格式。**

### EVMbench 的关键数字

- 数据集：40 次专业审计中筛选出的 120 个漏洞场景
- 2026 年初发布时，Agent 在 exploit 模式成功率 **72.2%**（相比早期 <20%，约 3.5 倍提升）
- **但是**：2026 年 3 月独立研究者用 22 个**模型训练截止之后**发生的真实事故重测，
 **没有一个 Agent 能完成端到端利用**。检测表现也大幅波动。

> 这个"但是"极其重要。它说明：**之前的高分里，有相当一部分是背答案背来的。**
> 一旦换上模型没见过的新题，分数就塌了。

**这就是第 3 代的根本缺陷：题目还是"死"的，只是换了个判卷方式。**

---

## 第 4 代：合成 + 动态对抗（⭐ 我们在这里）

### 核心洞察

> 既然真实数据一定会被污染，那就别用真实数据。
> **让题在考试开始那一刻才生成 —— 用不完、背不到、每次都新鲜。**

### 怎么做到"现出题还知道答案"？

这是 mine-engine 的解法，也是整个项目最精巧的地方：

```
① 拿一个"健康"的合约（已知没漏洞、功能测试全过）
 ↓
② 做一次最小的程序变换，主动"埋"一个雷进去
 （例：把"余额清零"这行从外部调用前，挪到调用后 → 造出重入漏洞）
 ↓
③ 差分验证 —— 这是灵魂：
 · 未注入版：攻击失败 ✓
 · 注入版：攻击成功 ✓
 · 原有功能测试：全过 ✓
 → 三条同时成立，才能证明"这个雷确实是我这次埋的"
 ↓
④ 因为雷是我们埋的，ground truth 天然就有：
 类型、严重级、文件、函数、行号、PoC —— 全部自动产生，不用人标
```

**这一步解决了三个问题**：
1. **答案不用人标**（埋的时候就知道了）
2. **答案一定是真的**（差分验证过了才算数）
3. **题可以无限生成**（换 seed、换算子、换变体）

### 第二个关键机制：对抗筛题（Adversarial Filtering）

借鉴 Humanity's Last Exam（HLE）的做法：

```
新生成一道题
 → 先让几个便宜模型做一遍
 → 如果全都答对了 → 这题太简单，标记 trivial，淘汰或加难
 → 如果有模型答错 → 这题有区分度，标记 differentiating，留进正式考卷
```

我们的 `run_ai_filter.py` 已经实现了这一步。
看实际数据：`sample-0002`（访问控制缺失）被标为 `differentiating`——
两个模型一个对一个错，说明它真的能区分模型强弱。**这就是好题。**

### 同路人验证：我们不是孤军奋战

**FinancialAuditBench**（Modus Audit × UIUC × Stanford, 2026）——这是你最该知道的对照：

> 它在**财报审计**赛道，用了**几乎一模一样**的方法论：
> 用**差分隐私**从历史真实审计中提取聚合统计作为先验，
> 加上 **1100+ 小时**审计专家投入，生成一个"计算图"来合成出内部一致的假公司及其全部财务凭证。
> 90 个任务，6 个合成 engagement，每个平均 179 个文件。
> 11 个前沿模型实测：最好的 Pass@1 只有 **69.17%**，pass^8 掉到 **44.44%**。

**这给了两件事**：
- ✅ "合成 + 可验证"这条路已被顶会级工作验证，不是野路子
- ⚠️ 他们在财报赛道已经做到 90 题 × 179 文件，我们在合约赛道是 7 题。**规模差距是数量级的**

**我们的差异化在哪**：他们做的是"一次性合成数据集"，我们做的是**引擎**。
引擎=可以持续产出；数据集=产出一次就固化（最终也会被污染）。
这个区别要在对外叙事里讲死。

---

## 第 5 代：共演化 + 跨赛道（🎯 我们要去的地方）

### 方向一：注入漏洞方 ↔ 审计方互相升级

```
注入漏洞方出题 → 审计方答题 → 审计方答对的题被淘汰 → 注入漏洞方被迫出更难的题 → 循环
```

这就是"可验证审计演化"。好处是**难度自动爬升，永远不会饱和**。
（你仓库里的 `seven_-audit` 已在做 RSI 递归自改进，可以合流。）

### 方向二：一套引擎，多条赛道

四组件抽象（`Generator / Operator / Validator / Scorer`）是领域无关的。
换一套实现，就能换赛道：

```
智能合约审计 → 已有（3 个算子）
国家审计 → 在财政资金账套上埋"违规"
企业审计 → 在财报/凭证链上埋"舞弊"
审计师 → 在工作底稿上埋"程序错误/证据链断裂"
```

**判断标准**：一个赛道能不能做，只看一件事——
**有没有一个"能自动跑的验证器"来证明雷真的存在。**
见 [04-three-tracks.md](./04-three-tracks.md)。

## 一张图总结

```
第0代 人出题人判卷 质量高 · 不可扩展
 ↓
第1代 静态题库 可扩展 · ❌会被背答案(contamination)
 ↓
第2代 LLM当裁判 能评主观题 · ❌标准主观，好看就能得分
 ↓
第3代 沙箱+可执行验证 客观了 · ❌题还是死的，照样被背 ← Harbor/EVMbench 在这
 ↓
第4代 现出题+差分验证 ✅背不到 · ⚠️我们规模太小 ← mine-engine 在这
 ↓
第5代 共演化+跨赛道 难度自动爬升 · 一套引擎多条赛道 ← 我们要去
```

**一句话**：前四代都在解决"判卷公不公平"，第四代开始解决"题目能不能被背"，
第五代要解决"题目能不能自己变难、并且换赛道还能用"。
