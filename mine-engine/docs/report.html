1我们要解决的病：benchmark 会腐烂

所有公开 benchmark 都有同一个绝症——题目会泄漏进训练语料，分数虚高。

决定性证据：EVMbench（OpenAI × Paradigm, 2026）发布时，Agent 在 exploit 模式 成功率 72.2%（相对早期 <20% 提升约 3.5 倍）。看起来 AI 快能审计了。

但 2026 年 3 月，独立研究者用 22 个模型训练截止之后发生的真实事故做无污染重测， 扩到 26 种 Agent 配置——结果：没有任何一个 Agent 能完成端到端利用，检测表现也剧烈波动。

之前的高分里，有相当一部分是背答案背来的。 一旦换上模型没见过的新题，分数就塌了。

同类证据还有：CI-FSFD（Forvis Mazars × LORIA）指出财报舞弊检测领域普遍存在 随机切分导致的高估；Harbor-Index 筛出的 82 道难题，没有任何模型-harness 组合超过 30% 通过率。

最强旁证：ALE 自己都怕污染，只敢公开 10% 的题

ALE（Agents' Last Exam）——UC Berkeley RDI / Dawn Song 组，1,490 个任务、 55 个子领域、13 个行业集群，由 250–300+ 行业专家从真实完成过的项目中出题。 注意：不是 Sakana 的 ALE-Bench

ALE 层通过率AuLE 对应我们现状
Near-Term（59 题）~30%Level 1 Detect 模型 F1=1.0，太易 应降级为"训练题"而非评测题
Full-Spectrum（55 题）~20%Level 2 Exploit 打穿率 50–83%，接近
Last-Exam（36 题）~2.6%Level 3 端到端 刚起步，两模型满分 远不够难
最扎心的数字：Codex + GPT-5.5 在 Terminal-Bench 上 82%， 在 ALE Last-Exam 上 0%。

而它防污染的办法是：1,490 题里只公开 150 题（约 10%），其余留作 held-out。 这意味着 ALE 有 90% 的题目无法用于公开评测——因为一公开就会被污染。

这就是我们的论文切口：ALE 用"少公开"这种笨办法防污染，代价是 90% 题目不能公开评测； 我们的引擎路线是 100% 可公开评测且不怕被背——因为题是每次现生成的。 这是结构性优势，必须写进 related work。

ALE 的三条纪律，我们已遵守但没讲出来：

  • 能代码判的绝不用 LLM 判；必须用 LLM 时用窄粒度 yes/no probe，不做整体打分 → 我们的 Foundry 差分正是 ALE 说的 "Executable / Behavioral" 评分模式
  • Gate-and-score：硬前置（如 PoC 编译）不过直接 0 分，过了 gate 才评质量 → 待加
  • 反作弊审查：主动构造"作弊解法"验证指标不会被刷 → 我们有诱饵，但缺系统性审查

我们的解法：让题在考试开始那一刻才生成

① 拿一个"健康"的合约（已知没漏洞、功能测试全过）
        ↓
② 做一次最小的程序变换，主动"埋"一个雷进去
   （例：把"余额清零"这行从外部调用前，挪到调用后 → 造出重入漏洞）
        ↓
③ 差分验证 —— 这是灵魂：
      · 健康版：攻击失败   ✓
      · 埋雷版：攻击成功   ✓
      · 原有功能测试：全过 ✓
   → 三条同时成立，才证明"这个雷确实是我这次埋的"
        ↓
④ 因为雷是我们埋的，ground truth 天然就有：
   类型、严重级、文件、函数、行号、PoC —— 全部自动产生，不用人标

这一步同时解决三个问题：答案不用人标、答案一定是真的、题可以无限生成。

2研究演进脉络：五代人怎么跟"作弊"打交道

评价一个 AI 会不会审计，本质就是给它出一场考试：题目从哪来？怎么判卷？能不能作弊？

同路人验证：我们不是孤军奋战

FinancialAuditBench（Modus Audit × UIUC × Stanford, 2026）在财报审计赛道用了 几乎一模一样的方法论：差分隐私从历史真实审计提取聚合统计做先验 + 1100+ 小时专家投入 + 计算图合成假公司及其全部财务凭证。90 个任务、6 个 engagement、每个平均 179 个文件。 11 个前沿模型实测：最好 Pass@1 只有 69.17%。

这给了两件事：① "合成 + 可验证"这条路已被顶会级工作验证，不是野路子； ② 他们在财报赛道已做到 90 题 × 179 文件，我们在合约赛道是 7 题——规模差距是数量级的。

我们的差异化：他们做的是"一次性合成数据集"，我们做的是引擎。 引擎 = 可以持续产出；数据集 = 产出一次就固化（最终也会被污染）。这个区别必须讲死。

3现状审查：我们已经有什么，缺什么

结论：架构是对的、可扩展性是对的，数据规模和方法论严谨度是短板，判分器有真实 bug。

最有价值的资产：四个领域无关组件

ArtifactGenerator  生成/加载"健康基准体"（干净、能正常工作的材料）
IssueOperator      在健康体上注入一个已知问题 + 产出 ground truth
IssueValidator     差分验证：雷在埋雷版可触发、在健康版不可触发、原有功能仍通过
ReportScorer       把审计报告对 ground truth 判 recall / precision / F1

换掉这四者的实现，同一套编排层就能从智能合约审计切到财报审计、国家审计、审计师底稿复核。 这应当被提升为项目的第一叙事。

5三条赛道：国家审计 / 企业审计 / 审计师

核心判断标准：一个赛道能不能做，只看一件事——有没有能自动跑的验证器。

L2 · 最易做

企业审计

内审 / 风控 / 反舞弊

健康体：真实勾稽的制造业账套（总账 / 明细账 / 凭证 / 合同 / 银行流水）

埋什么：收入提前确认、费用资本化、少提减值、循环交易、 关联交易非关联化、存货虚增、不相容职务未分离、审批链断裂

验证器全可计算：三表勾稽 + 凭证链五单齐全且日期单调 + 红旗指标越界 （Beneish M-Score / 应收账款周转突变 / 毛利率偏离）

数据：上市公司财报+XBRL、证监会处罚决定（真实舞弊手法语料，金矿）

MVP：4 算子 × 8 seed = 32 题 + 8 诱饵

L3 · 独家赛道

国家审计

审计署 / 审计厅 / 财政资金

健康体：合规的部门预算执行账套（预算指标 / 拨付流水 / 凭证 / 合同 / 验收单）

埋什么：虚假列支、截留挪用、规避招标、超标支出、 资金滞留、虚报进度、违规发放、债务隐匿

双闸门：A 资金流勾稽（预算指标=下达=拨付=支出=决算，借贷平衡）+ B 法规条款命中（违规事实 ↔ 公开法条库）

数据：审计署《审计结果公告》、部门预决算公开、政府采购公告、公开法规库

政策窗口：浙江 2026"智能审计工程"、山东"加快审计智能体升级"； 中国审计学会"人工智能时代的审计（2026）"收到 596 篇论文、入选 35 篇

⚠ 合规红线：绝不把真实审计数据做成公开数据集。只取差分隐私聚合先验，账套全部合成。
L4 · 最难做

审计师

CPA / 事务所 / 工作底稿

健康体：一份正确完成的审计工作底稿（风险评估 / 程序 / 证据索引 / 结论）

埋什么：程序遗漏、样本不足、证据断链、结论与证据矛盾、 计算错误、日期倒挂、擅自变更程序

三闸门：A 四段链可追溯（风险→程序→证据→结论，每段存在且指向一致）+ B 持牌 CPA rubric + C review 模式（给"已完成"底稿挑错，成本更低、区分度更高）

成本：需持牌审计师投入（FinancialAuditBench 用了 1100+ 小时）。 缓解：rubric 按任务类型复用，专家投入是一次性的

MVP：3 科目 × 5 算子 × 6 seed = 30 题，半数 review 模式

5.5合成环境不只是"出题"，还要"体检"

对标 AWM（arXiv:2602.10090，1,000 个全合成环境）与中科院自动化所综述（arXiv:2606.12191）

本轮最重要的发现：我们做出了四条验收线里最容易的一条。 中科院综述把合成环境的评价分成四维，并坦承 "正确性的评估方法已相当成熟，多样性 / 复杂性 / 忠实度的定量评估仍处于早期"—— 而我们稳住的恰好是正确性这一维，难的三维基本没碰。
✅ 正确性
题可解吗？判分对吗？

FoundryDiff 编译 + 测试差分，是我们最强的资产。 缺 blocked rate（连黄金解答都跑不通的废题率）——AWM 把它当成信号可靠性的头号指标。

0.37 多样性
池子是不是全是同一类题？

类别均衡度 0.975 很高（雷型分散）， 但结构离散度只有 0.173——雷型分散，代码结构却高度同质。 这是典型的 mode collapse 前兆，AWM 靠 embedding 去重 + 类别上限防它。

0.37 复杂性
难度梯度铺开了吗？

5 档难度只占了 2 档。全简单→天花板效应， 全难→地板效应，两种情况下这道题对排序的贡献都是 0。

忠实度：完全没被度量，而它是唯一能摧毁整个方法论的维度。
综述原话：一个软件工程环境里的任务，即使技术上可以运行， 如果它的 bug 模式与现实项目中的 bug 完全不同，这个环境就缺乏忠实度。
换成我们：合成合约能编译、能触发重入、能拿 POC—— 但如果它跟真实链上合约长得不像，我们测出来的分数能不能外推到真实审计？ I9 · 差异化最强

ALE-Bench 这一节是本次最大的增量：它解决了 ALE 没解决的问题

ALE 解决的是"别作弊"。但还有个更根本的问题 ALE 没管——分数会饱和。 ALE-Bench 的答案是三条，而这三条我们一条都没做：

我们缺

① 连续分 + 开放式上限

它的题是 NP-hard，真最优解算不出来，所以分数永远有上升空间—— AI 超过人类之后 benchmark 依然有效。

我们的 exploit 模式仍是 pass/fail 二值，题一生成天花板就定了。
我们缺

② 时间预算必须报

同一批题，只改时间预算：

1 小时58.8
几小时77.7
几天87.6
1 周92.1
这就是"长时程推理"的可测量定义。 我们 run_benchmark 没记 wall-clock。
我们缺

③ 成本必须报

只报分数是失真：

OpenHands905 分$3.25/题
Self-Refine1198 分$11.10/题
ALE-Agent1879 分$100.33/题
贵 30 倍换 2 倍分，值不值取决于预算。 我们的报告两轴都没有。
但我们有两张它没有的牌。 ALE-Bench 的开放式上限是题目自带的（NP-hard）、不可调； ALE 的三层难度是离散的、题目固定。 而我们是题能换（埋雷引擎 + 固定 seed，可再生）且难度能连续调 （雷数 / 跨函数距离 / 诱饵密度 / 混淆度 / 变体强度）。

在 [09 · 三坐标手册](./09-synthetic-env-playbook.md) 的总表里， 这是唯二标 ⭐「我们更强」的两行——对外叙事必须站在这两行上。
已落地：engine/analytics/openended.py —— 时间轴（边际收益 / 每翻倍涨多少）、 饱和检测（三点法拟合渐近线，ALE-Bench 自己的曲线被正确判为 saturated）、 成本帕累托前沿、Performance Elo 归一化。
还差：把它们接进 run_benchmark（约 1 小时，见 I12）。

I1 可再生基准 + CRS 指标
🥇 先做		 把"benchmark 腐烂速度"变成可测量的量：CRS = 1 − |S_原题 − S_换seed新题| / S_原题。 这个指标只有引擎型 benchmark 能算，静态数据集算不了。 522
I4 Skill 触发可靠性
🥈 顺手做		 实测发现 83 个审计 skill 的首要瓶颈是"压根没被触发"。把"触发"本身当成被评测对象。 322
I6 难度 IRT 化
🥈 与 I1 配套		 用 Rasch 模型把题目难度与模型能力放到同一把尺子，自动挑信息量最大的题， 30 道高信息量题 ≈ 100 道题的区分效果。 332
I2 验证器硬度阶梯
🥉 撑叙事		 L1 编译器→L2 勾稽→L3 法条→L4 rubric。核心实验：同一个 Agent 在四级上的表现排序， 是否与其"自称能力"一致？给出分层的"AI 能不能做审计"答案。 543
I5 自动化顺从度量
🥉 新颖度最高		 KPMG×UT Austin 研究：523 名新人中 25.8% Delegator（照单全收）、24.1% 比 AI 单独做还差； PCAOB 委员公开质疑"没做过基础程序的审计师如何复核 AI"。
实验灵魂：给底稿附加不同"权威信号"（"资深经理已复核" vs "AI 生成请复核"）， 看错误发现率是否显著下降。		 532
I3 埋雷–审计共演化 答对的题淘汰，埋雷方被迫出更难的题，难度自动爬升。研究"能力-难度军备竞赛"的动力学。 444
I7 GovAudit-Bench
对外先讲		 中国国家审计赛道公开 benchmark 为零，但甲方和政策驱动都在。 有现成投稿通道：中国审计学会"人工智能时代的审计"专题。 554
I8 自我修正循环
⚡ 半天		 验证失败时把 forge 的 stderr + 源码喂回 LLM 让它修自己的埋雷代码。 AWM 平均 1.13 次迭代即可修复。不做这个，扩题池会被算子成功率卡死。 211
I9 忠实度度量
💎 差异化最强		 所有 benchmark 论文都默认"我的题能代表真实任务"， 没人把这个假设本身当研究对象。用真实漏洞做只读锚点， 算「合成题 ↔ 真实题」分布距离，并做跨域迁移检验。 这是 I1 论文的记忆点。 533
I10 成本—质量前沿
可并入 I1		 AWM 明确承认没研究"环境生成成本 vs 最终性能"。 把「每题生成成本 vs 该题区分度」画成散点找拐点， 回答一个所有人都想知道但没人答的问题：造一道好题要花多少钱？ 322
I12 时间—成本双轴
1 小时		 ALE-Bench 是少数同时报时间和成本的 benchmark，我们两样都没有—— 分数因此不可比。记录 wall-clock + token 成本，画时间—分数曲线， 分数用 Elo 锚到人类分布报 "Top X%"。模块已写好，接线即可。 211
I11 难度连续旋钮
我们独有的牌		 ALE-Bench 靠 NP-hard 让分数永不饱和，但它的难度不可调； ALE 的三层难度是离散的。我们把埋雷算子参数化 （雷数 / 跨函数距离 / 诱饵密度 / 混淆度 / 变体强度）， 题能换 + 难度能连续调两者兼得。测"难度刻度 → 模型分数"曲线。 532
组合打法。第一步（本周）：I8 自我修正循环，半天做完，直接把算子成功率拉起来； 短期（1–2 月）：I1+I4+I6+I9 打包成方法论文 "Benchmarks Rot: Regenerative Evaluation for Audit Agents"； 中期（3–5 月）：I2 撑框架，做出 L2 企业审计 adapter； I5 单开投 CSCW/CHI；I7 走政策通道。
对外叙事顺序：先讲 I7 国家审计（独家、有甲方）→ 再用 I1 可再生（方法论硬核）建立学术 credibility → 最后用 I2 硬度阶梯收尾，证明这不是一个点子而是一个方向。 对外叙事顺序：先讲 I7 国家审计（独家、有甲方）→ 再用 I1 可再生（方法论硬核）建立学术 credibility → 最后用 I2 硬度阶梯收尾，证明这不是一个点子而是一个方向。

设计原则：判分严格度不能超过 ground truth 的标注粒度。 我们的 gt 是函数级区间，模型报该区间内任意行即算命中——不能再苛求行号精确。 行号精度若需衡量，应另设指标，而不是让它主导 F1。

四条原则（写给自己）

  1. 先能说，再做深。叙事层（文档 + Harbor 兼容）零代码就能拿分，优先做。
  2. 规模是硬伤。7 题不支撑任何结论，M8 之前不对外发布任何"模型能力"结论。
  3. 不碰真实敏感数据。所有赛道一律走"合成 + 差分隐私先验"， 这是 FinancialAuditBench 已验证的合规路径。
  4. 新增算子不改编排层。这是四组件抽象的价值所在。 一旦出现"为了加一个算子改了 pipeline"，说明抽象漏了。
