## 1. 名字消歧表（写论文前必须背下来）

⚠️ 本项目历史上**四次**因引错名字导致定位错误。以下六个名字**互不相关**。

| 名字 | 性质 | 出处（已核实） | 一句话 |
|---|---|---|---|
| **ALE** | 评测**基准** | arXiv:2606.05405，Berkeley RDI，Dawn Song 组，v2 2026-06-11 | 1490 个真实专业工作 `task instance`，只公开 150（**10.07%**）；13 industry clusters / 55 subdomains（51 SOC-anchored + 4 frontier） |
| **ALE-Bench** | 评测**基准** | arXiv:2506.09050，Sakana AI × AtCoder，**NeurIPS 2025** | 40 道 AHC 启发式赛题，score-based 无最优解，框架可 long-horizon 迭代 |
| **Harbor** | 评测**框架** | `laude-institute/harbor`（Apache-2.0，Meta / Alex Shaw 等） | 跑 agentic eval 与 RL rollout 的 harness；Terminal-Bench 2.0 的官方 runner |
| **agentic data** | **数据对象定义** | arXiv:2608.27260，Zeng et al.（2026-08-27） | `d = (E, q, τ, v)`：环境 / 任务信号 / 交互实现 / **可选 verifier** |
| **AWM** | 环境**合成**流水线 | arXiv:2602.10090，UNC + Snowflake，ICML 2026 | 批量造世界模型式环境 |
| **AutoBenchmark** | **端到端出题** | Meta RAM 博客，Jason Weston 组 | research agent 自动造 benchmark，产 Harbor 包；技术报告未发 |

### 1.1 三个极易搞混的 ALE

- **ALE** 与 **ALE-Bench** 是**两个不同团队的不同基准**，名字撞车但无关。
  ALE 出自 Berkeley，ALE-Bench 出自 Sakana×AtCoder。**绝不并列成"ALE 系列"。**
- **ALE-Bench 与 ALE 都含 "Agents' Last" 字样但含义不同**：
  前者 = ALgorithm Engineering Benchmark，后者 = Agents' Last Exam。
  首次出现必须写全称 + arXiv 号。

### 1.2 🔴 AgentFlow 有两个同名工作（2026-10-05 新发现，极易引错）

| | **AgentFlow（A）** | **AgentFlow（B）** |
|---|---|---|
| arXiv | **2608.22868** | **2604.20801** |
| 标题 | *A Flow-Centric Policy Language and Framework for Securing LLM Agent Systems* | *Synthesizing Multi-Agent Harnesses for Vulnerability Discovery* |
| 作者 | Shivakumar, Priya, Gao | Hanzhi Liu, Chaofan Shou, …, **Yu Feng** |
| 做什么 | **安全**：数据流策略语言 + SMT 验证 | **harness 搜索**：typed graph DSL 搜多 agent 编排 |
| 关键数字 | AgentDojo 949 例，妥协率 33.0%→0.0%，效用 46.7%→63.3% | TerminalBench-2 **84.3%**；Chrome 10 个零日（含 2 个 Critical 沙箱逃逸） |

⚠️ 我们只与 **B（2604.20801）** 有关系（都是"用 agent 找漏洞"），
但**它测的是 harness 搜索，不是 verifier 可靠性**，不构成直接竞争。
引用时必须带 arXiv 号，否则读者无法判断引的是哪个。

### 1.3 消歧规则

- 首次出现：**全称 + 团队 + arXiv 号 / repo 名**，三者缺一不可。
- 后续出现：可简称，但**不得在同一段里出现两个易混名**。
- Related work 表里每行必须有**可点击的稳定标识**（arXiv ID 或 DOI）。

## 4. 数字纪律

### 4.1 每个进入论文的数字必须附的元信息

```
数值 + 样本量 n + 统计量定义 + 是否重复运行 + 置信区间 + 数据来源文件
```

示例（合格写法）：

```
FNR_det = 0.500, 95% CI [0.423, 0.577], n_clean = 120, n_inj = 100,
每题重复 3 次取多数投票，来源 results_s1_flash.json
```

反例（不合格）："判分器漏报率约 50%" ← 无 n、无 CI、无口径、不可复核。

### 4.2 重复运行与确定性

⚠️ **`temperature=0` 仍不确定**（本项目实测发现）。
所有 LLM 判定必须：**每题重复 ≥3 次取多数投票，并报告分歧率**。

### 4.3 符号约定（务必统一，历史上混淆过）

| 记号 | 含义 | 等价写法 |
|---|---|---|
| `FNR` | 真实有错却判对（漏报） | 噪声修正文献的 `ρ⁻`、`τ⁻` |
| `FPR` | 真实无错却报错（误报） | 噪声修正文献的 `ρ⁺`、`τ⁺` |
| `J = 1 − FPR − FNR` | Youden's J index（Youden 1947, *Cancer*） | 我方旧记号 `τ`（**建议弃用 τ，专留 J**） |
| `e2e = 1 − (1 − det)(1 − attr)` | 端到端与分层的关系 | 实测吻合到三位 |

⚠️ **不要用 `τ⁺/τ⁻` 这套写法**——只有 `ρ⁺/ρ⁻`（噪声率）与 `τ`（保留因子）两套记号混用会造成误读。
**建议：本文一律用 `J`**，需要引文献时写"文献记为 ρ⁺/ρ⁻"。

### 4.4 J 必须分层报，且必须写明符号归属

| 模型/arm | FNR_det | FNR_attr | FNR_e2e | FPR | **J_det** | **J_e2e** |
|---|---|---|---|---|---|---|
| flash A | 0.500 | 0.150 | 0.575 | 0.100 | +0.400 | +0.325 |
| flash B | 0.113 | 0.422 | 0.487 | 0.925 | **−0.038** | **−0.413** |
| flash C | 0.494 | 0.012 | 0.500 | 0.000 | +0.506 | +0.500 |
| pro C | 0.070 | 0.333 | 0.380 | 0.800 | **+0.130** | **−0.180** |

（数据来源 `results_s1_flash.json` / `results_s1_pro.json`）

**三条写作义务**：

1. **分层报，不可只报端到端**。pro 的检测层 J 是正的（+0.130），只在端到端层转负。
2. **J 的符号是 arm（提示配置）属性，不是模型属性**。flash B 负、C 正。
   ⇒ 只能写"该 verifier **在该提示配置下**判别力为负"。
3. **J<0 有两种成因，必须区分**：
   - (a) 真极性反转 → 取反可修复；
   - (b) FPR 主导的过度敏感 → 取反更差。

   ⚠️ **pro 属 (b)**：实测取反后 FNR=0.800 / FPR=0.070，比原来更差。
   ⇒ 不得笼统写"J<0 ⇒ 降级为审阅级"。

### 4.5 🔴 设计参数必须标注为"未标定"

`DEPR_MIN_RATIO = 0.5`（折旧下限宽松系数）是**设计参数，不是实测标定值**。
论文里必须显式写 "a design parameter, not empirically calibrated"，
且必须附 F4 验收数字证明它**既不恒真也不恒假**。

### 4.6 口径声明（必须原文明写，不得省略）

- 我们的耗时是 **execution wall-clock**，不属于长时程任务三种标准口径
  （human-time / token / episode）中任何一种 ⇒ **不得声称与 human-time 对齐**。
- σ=0 学界叫 **zero-variance / degenerate group collapse**；
  `2510.18924` 只在介绍 Dr.GRPO 时提过一句，**我们只能声称"提供实证与规模刻画"，
  不能暗示机制是我们发现的**。

## 5. 贡献表述纪律

### 5.1 每条主张必须配"什么数字能杀死它"

| 我们的主张 | 杀死它的数字 |
|---|---|
| 判分器误差随难度变化 | 四档的 FNR 无显著差异（曲线是平的） |
| 难度可连续参数化 | 参照层四档不可区分（**F4 已过：4/4 分离、6/6 两两可区分**） |
| 存在 J<0 反转区 | 补样本后 J 的 CI 覆盖 0（**当前 pro CI 下界 J=+0.057，尚未钉死**） |
| 零人工可测误差率 | 必须人工标注才能对齐（参照审计已否定：构造真值即可） |
| σ=0 退化区有规模刻画 | 100% 退化组样本不足（**已有，n 需补**） |

### 5.2 三条被推翻的旧结论（**禁止再引用**）

| 旧说法 | 实际 | 出处 |
|---|---|---|
| "误报会把训练方向带反，是我们的发现" | **τ=1−FPR−FNR>0 时理论上永不翻转**，噪声只降固定点高度 | arXiv:2510.18924 |
| "系统性误报导致崩溃是新的" | 已被实证，且**由 pattern 而非错误率决定** | arXiv:2605.02909（COLM 2026） |
| "会计域没人测 / 没人用免人工参照" | FinVerBench 已在会计域测（43 家 S&P500 真实 XBRL）；免人工参照已有人做 | 2605.29586 / 2609.01354 |

### 5.3 五条不可越界的红线

1. **不得声称"让注入更有效/更真实"**。变异体有效性已被 arXiv:2406.09843（TOSEM/JFCS，
   851 真实 Java bug，LLM 检出 87.98% vs 规则 41.64%）做透。
   我们只卖 **judge adequacy**（测判分器），而变异测试只测 **test suite adequacy**。
2. **不得把两个"审计"并列**。`engine/operators/` 是 Solidity 漏洞 = 区块链安全
   （英文**不可写 audit**）；`vts/audit_core.py` 是复式记账舞弊 = **financial statement audit**。
   中文分称"合约漏洞检测"与"财务审计"。
3. **不得说"会计域是空的"**。只能说"**判分器的误差率与难度依赖性未被测**"。
4. **不得把"AutoBenchmark 证明 agent 能自己出题"当我们的卖点**。该路线已被做完整。
5. **不得声称我们的 J<0 是"新发现的方向反转"**。定理已证。
   贡献只能写"**首次在 LLM verifier 上测出判别力跨过 d′=0**"。

### 5.4 允许的三个造词

只允许这三个（是方法命名不是比喻，首次出现给形式化定义）：
**差分隔离证书 / 难度连续参数化 / 三域统一框架**。

其余一律换成领域标准词：踩雷率→FPR、健康体→vulnerability-free baseline、
诱饵→hard negative、变体→semantics-preserving variant、旋钮→IRT item difficulty bᵢ。

### 7.1 先建立一个类比：考试院

评测这件事可以拆成三件互不相同的工作：

| 环节 | 类比 | 谁在管 |
|---|---|---|
| **造题** | 出考卷、决定考什么 | ALE、agentic data 的 `E, q` |
| **判分** | 阅卷、给分 | Harbor（执行判分程序）、agentic data 的 `v` |
| **跑考务** | 排考场、发卷、收卷、计时 | Harbor |

**关键认知：这三件事里，"判卷老师自己有没有看错"从来不在任何一个人的职责里。**
出题的不管判分，管判分的只负责跑程序，跑考务的只管流程。
⇒ **这正是我们的位置。**

### 7.2 三个外部系统各自回答什么问题

**ALE（arXiv:2606.05405）回答"考什么"**
- 1490 个真实专业工作实例（`task instance`），来自 250+ 位行业专家；
  按 O*NET/SOC 2018 职业分类建成 13 个行业集群、55 个子领域。
- 三层难度：Near-Term / Full-Spectrum / Last-Exam。
  最难一层主流配置 full-pass rate **低于 1%**（最高报 2.6%，多数 0.0%）。
- ⚠️ **它只公开 150 / 1490 = 10.07%**，其余私有并**滚动轮换**，
  理由是防污染（benchmark contamination）。
- 它给出的验证方式是：尽量用**确定性检查**，少数场景才用 LLM judge，
  且用**基于证据的窄 yes/no 探针**而非"整体好不好"的宽泛提问。
- ❗**但它不报告 judge 自身的误报/漏报率，也没有任何标注一致性统计。**

**Harbor（`laude-institute/harbor`）回答"怎么跑"**
- 它是**框架**，不是基准。Terminal-Bench 2.0 的官方 runner。
- 每个任务一个目录：`task.toml`（配置）+ `instruction.md`（给 agent 的题）+
  `Dockerfile`（沙箱）+ `tests/test.sh`（判分程序）+ 可选 `solve.sh`（参考解）。
- 三阶段执行：**建镜像（600s）→ agent 跑（900–12000s，按任务配）→ 验证**。
- 产出两个文件：`/logs/verifier/ctrf.json`（明细报告）与
  `/logs/verifier/reward.txt`（**0 或 1 的二值奖励**，供 RL 用）。
- 隔离保证：每任务全新容器、默认**无网络**、文件改动不外泄。
- ❗**它不评判判分器对不对**——它只负责"忠实执行判分程序并记下结果"。

**agentic data（arXiv:2608.27260）回答"一份 agent 交互数据由什么组成"**
这是**概念定义**，不是系统。定义 `d = (E, q, τ, v)`：

| 分量 | 含义 |
|---|---|
| `E` | **环境说明书**：工具、状态、规则 |
| `q` | **任务信号**：agent 要达成的目标 |
| `τ` | **交互实现**：实际的动作与观察序列 |
| `v` | **verifier**：检查成功与否的判定器 ——**原文标注为 optional** |

- 配套 **ACE 视角**：`Accuracy`（可行支撑：数据是否 grounding 且自洽）、
  `Complexity`（相对学习者能力与执行配置的学习负担）、`divErsity`（覆盖与冗余）。
- ❗**关键**：因为 `v` 是 **optional**，它就可以被"假设存在"而不被测量。
  综述了前人如何验证生成的经历、如何构造与校准难度、如何扩展行为覆盖，
  **但没有测过 verifier 自身的误差率**。

### 7.3 于是我们的位置是唯一闭合的

把三件事接起来看：

```
造题（ALE 管内容，agentic data 定义 E/q）
  → 判分（Harbor 跑 v，agentic data 说 v 是可选的）
    → 🔴 没人测 v 到底错多少  ← 我们在这里
```

我们的做法不需要任何人告诉我们答案对不对，**只需要问同一个判分器两次**：

1. 给它一份**干净**账套 → 它报错了 ⇒ **误报率 FPR**（干净时的报错就是纯误报）
2. 给它一份**注入过已知舞弊**的账套 → 它没报出来 ⇒ **漏报率 FNR**

参照答案由**会计恒等式程序化推导**（7 条 oracle），不是人标的 ⇒ 零人工标注。

### 7.4 为什么这件事有学科分量

不是自造概念。三个现成的学术对应：

1. **FNR = 审计准则里的"检查风险"**。PCAOB AS 1101 原文：
   `Audit Risk = RMM × Detection Risk`，而 Detection Risk 定义为
   "procedures…will not detect a misstatement that exists" ——
   **在学科里它就叫检查风险**。准则把它列为乘数项但行业只能定性对待；
   我们用构造性参照把它算成**带置信区间的实数**。
2. **`J = 1 − FPR − FNR` 就是 Youden's J index**（Youden 1947, *Cancer*）。
   `J = 0 ⟺ d′ = 0 ⟺ ROC 落在随机对角线`；`J < 0` 学界叫 `reversed discrimination`。
3. **自造词只有三个**，其余全部用领域标准词（见 §5.4）。
