## 1. 基础设施层：Harbor（必须接入的那个）

| 项 | 内容 |
| --- | --- |
| 是什么 | **评测执行器**（harness），不是数据集。Terminal-Bench 团队出品 |
| 定位 | "用任意 agent + 任意 model，在任意沙箱里跑任意任务" |
| 任务三元组 | `instruction.md`（给 AI 的题） + `sandbox`（Docker 沙箱） + `verifier`（判卷程序） |
| 生态位 | 官方 Terminal-Bench 2.0 的 harness；已适配 54+ benchmark、80+ adapters |
| 云沙箱 | Docker 本地 / Daytona / Modal / E2B / LangSmith / Runta，可千路并发 |
| 输出 | 每次 trial 的 pass/fail、耗时、token、完整 trajectory（可喂 RL） |
| 代表观点 | LangChain CEO Harrison Chase：*"每家做关键任务 Agent 的公司都会建自己的 benchmark"*；Harbor 的共同创造者 Alex Shaw：*"Agent 开发更像机器学习，而不是软件工程"*（因为输出不确定，只能靠经验评测） |

**对我们的意义**：
Harbor 正在成为"跑分"的标准插座。我们的题**必须**能导出成 Harbor 格式，
否则就只能在自己的脚本里自娱自乐。
→ 这是 M7 的必做项（见 06-roadmap）。

**最新相关论文**：*Harbor Adapters and Harbor-Index*（arXiv:2609.04298）——
把 80+ benchmark 移植到统一基建，8 个模型 × 54 个 benchmark 大规模评测，
并筛出 **82 个高难度任务**组成 Harbor-Index：**没有任何模型-harness 组合超过 30% 通过率**，
最强（GPT-5.5 + Codex）也只有 28.0%。
> 启示：行业已经从"造更多 benchmark"转向"从现有 benchmark 里筛出真正难的题"。
> 我们的 AI Filter 正是这条路线，可以顺势对接。

## 1.5 头号对标：ALE（Agents' Last Exam）

> **注意**：ALE 指 **Agents' Last Exam**（UC Berkeley RDI / Dawn Song 组，
> arXiv:2606.05405，2026-06），**不是** Sakana AI 的 ALE-Bench（AtCoder 启发式算法竞赛）。
> 两者简称撞车，别搞混。

| 项 | 内容 |
| --- | --- |
| 规模 | **1,490 个任务实例**，55 个子领域，13 个行业集群（O*NET / SOC 2018 美国职业分类法） |
| 题目来源 | **250–300+ 行业专家**真实完成过的项目（不是合成题），专家通过专门入口提交 |
| 三层难度 | **Near-Term** 59 题 ~30% 通过率 / **Full-Spectrum** 55 题 ~20% / **Last-Exam** 36 题 **~2.6%** |
| 最扎心的数字 | **Codex + GPT-5.5 在 Terminal-Bench 上 82%，在 ALE Last-Exam 上 0%** |
| 评分铁律 | **能代码判的绝不用 LLM 判**；必须用 LLM 时用**窄粒度 yes/no probe**，不做整体打分 |
| 七种 artifact 评分 | Exact/hashed、Structured tabular、Geometric、Visual、Behavioral、Free-text rubric、Executable |
| **防污染** | **1,490 题中只公开 150 题（约 10%）**，其余留作防污染 held-out |
| 任务生产五阶段 | 专家出题 → 初筛 Review → 工程实现 → 最终 QC（reproducibility + 评分校准）→ 反作弊审查 |
| Gate-and-score | 硬前置条件不通过直接 0 分（如 PoC 编译失败），过了 gate 才评质量 |
| 定位 | **living benchmark**：任务池随新行业接入持续增长；目标 5,000 题 |

### ALE 对我们的三重意义

1. **它自己就在防污染 —— 而且用的是"少公开"这种笨办法。**
 1,490 题只放 150 题出来。这从侧面证明了我们核心判断的正确性：
 *污染是行业公认的头号问题*。而 ALE 的代价是**10% 的题目能公开评测，90% 只能自己藏着**；
 我们的引擎路线是**100% 可公开评测且不怕被背**——这是结构性优势，必须写进论文 related work。

2. **"反 LLM-as-judge"是我们已经遵守但没讲出来的纪律。**
 我们的差分验证（Foundry 真跑）就是 ALE 说的 "Executable / Behavioral" 评分模式。
 对标 ALE 的七种 artifact 模式，我们目前用到：
 - `Executable`（forge test 差分）✅ Level 1 已用
 - `Structured tabular`（findings JSON 字段匹配）✅ 已用
 - `Behavioral`（攻击后余额变化）🔨 run_exploit 部分用到
 - `Free-text rubric`（报告质量）❌ 未做（Level 3 报告维度待实现）

3. **三层难度体系可以直接映射到我们的 Level 1/2/3：**
 | ALE | 通过率 | AuLE 对应 | 我们现状 |
 |---|---|---|---|
 | Near-Term | ~30% | Level 1 Detect | ❌ 模型 F1=1.0，**太易**，应降级为"训练题" |
 | Full-Spectrum | ~20% | Level 2 Exploit | ✅ 打穿率 50–83%，接近 |
 | Last-Exam | ~2.6% | Level 3 端到端 | 🔨 刚起步，两模型满分，**远不够难** |

 **关键洞察**：ALE 的 Last-Exam 不是"更难的 Near-Term"，而是"大多数模型 0% 通过"——
 它锚定的是长期研究方向，不是日常调参。我们缺的正是这一层。

### 我们必须补上的三件事（对照 ALE）

- [ ] **Gate-and-score**：Level 3 评分改成 Gate（JSON 可解析？PoC 能编译？PoC 跑通了吗？）→ 才评质量
- [ ] **数据集版本化**：`datasets/v0.1 / v0.2 / v0.3` + README 记录每版 git hash、通过率、已知问题
- [ ] **反作弊审查**：主动构造"作弊解法"（如不读代码直接报所有函数有漏洞）验证指标不会被刷

## 2. 同赛道：智能合约审计

### EVMbench（OpenAI × Paradigm，2026）— 头号标杆

| 项 | 内容 |
| --- | --- |
| 数据 | 40 次专业审计中筛选的 **120 个漏洞场景**（多来自 Code4rena 竞赛）+ 主网事故 |
| 三模式 | **detect**（找漏洞，测 recall） / **patch**（修好且不破坏功能） / **exploit**（沙箱里真把钱转走） |
| 判卷 | 近乎二值：能不能真的利用 |
| 成绩 | 发布时 exploit 模式 **72.2%**（早期 <20%，3.5×提升） |
| **反转** | 2026-03 独立研究：扩到 26 种 Agent 配置，并用**22 个训练截止后的真实事故**做无污染重测 → **没有任何 Agent 能端到端完成利用**，检测表现剧烈波动 |

**行业共识（多方报道一致）**：
- 强项：访问控制 92% recall、算术错误 89% recall
- 弱项：跨合约重入 54%、经济激励操纵 41%
- **exploit 合成能力**：最强 Agent 仅 31% 成功
- **fix quality**：中等严重度修复正确率没有 Agent 超过 60%
- BlockSec 等审计公司公开立场：*"取代人类还差得远"*

**对我们的意义**：
1. ✅ 我们的 `run_exploit.py`（模型写 PoC + forge 真跑）与 EVMbench 的 exploit 模式**同构**，方法论站得住
2. ✅ "无污染重测分数塌方"就是我们的**最强论据**——可直接引用
3. ⚠️ 但 EVMbench 有 120 个场景，我们 7 个。别在规模上硬碰，要在**"可再生"**上打

### 有意思的旁支：审计 Skills 的触发率瓶颈

一项研究收集 **83 个智能合约审计 skill**，在 EVMbench 上跨 7 种 agent-model 配置测试，结论：
> **模型比 harness 更重要；而"skill 到底有没有被触发"才是主要瓶颈。**
> 最大提升 22.8% 检测分、43.2% 奖金捕获（Codex/GPT-5.5）。
> 那些真正被触发的 skill 共享一个六阶段审计工作流，但很多 skill 压根没加载。

→ 这直接启发了一个可做的研究点：**审计提示词/技能的"触发可靠性"评测**
（见 05-ideas 的 I4）。

## 3. 平行赛道：审计师（财报审计 / workpaper）

### FinancialAuditBench（Modus Audit × UIUC × Stanford，2026）— 最强对标 ⭐

| 项 | 内容 |
| --- | --- |
| 任务 | **90 个任务 / 6 个合成审计 engagement**，每个 engagement 平均 **179 个文件** |
| 两种设定 | **completion**（45）：给空白底稿模板，执行程序并记录结论<br>**review**（45）：给一份已完成的底稿，复核并纠正错误 |
| 判卷 | 持牌 CPA 设计的 **rubric** |
| 数据生成 | **计算图**合成假公司及其全部财务凭证；用**差分隐私**从历史真实审计提取聚合统计做先验；**1100+ 小时**专家开发评审 |
| 成绩 | 11 个前沿模型，最好 Pass@1 = **69.17%**，pass^8 = **44.44%** |
| 关键结论 | *"Agent 能完成相当部分 staff 级任务，但有时会执行不恰当的程序或产出错误文档"* |
| 开源 | MIT，数据集 + 代码全公开 |

**对我们的意义（最关键的三条）**：
1. ✅ **方法论同源**——"合成 + 内部一致 + 专家先验 + 可验证"，我们在合约赛道独立走到了同一处。这是强背书。
2. ✅ 他们的 **review 设定**（给一份做好的底稿去挑错）极其巧妙，我们**直接可以抄**到合约赛道
 （比如：给模型一份已完成的审计报告，里面埋了 3 个错误结论，让它复核）
3. ⚠️ 他们已经用差分隐私解决了"用真实机密数据做 benchmark"的合规问题——
 我们做国家审计/企业审计赛道时，这是**绕不开的同一道题**，必须提前设计

## 4. 平行赛道：企业审计（舞弊 / 内控 / 反舞弊）

| 工作 | 数据 | 任务 | 成绩 |
| --- | --- | --- | --- |
| **AuditFraudBench**（2026-06） | SEC **AAER 执法案例 84 例** + 原始/重述 10-K/10-Q + MD&A + XBRL | ① 利润来源归因 ② 误导性叙述检测 ③ 舞弊手法分类 | 任务1 标签准确率接近满分但机制解释弱；**任务2 最好仅 24.5%**；模型规模与推理能力**不能预测**审计判断力 |
| **FinAuditing**（SIGIR 2026） | 真实 XBRL 报送，**1102 例**，平均 33k tokens | ① 财务语义匹配 ② 财务关系抽取 ③ 财务数学推理 | 13 个 SOTA 模型在概念检索、taxonomy 关系建模、跨文档一致性上**差距明显** |
| **CI-FSFD**（Forvis Mazars × LORIA, 2026-07） | 美国公司财报 + MD&A 摘要 + 舞弊标签 | 提出"公司隔离"划分（CI-FSFD），替代随机划分 | 指出领域普遍存在**随机切分导致的高估**；文本数据价值被低估 |

**关键洞察**：
- AuditFraudBench 的任务 2 只有 24.5% —— 说明**"识别被刻意伪装成合规的舞弊"**仍是开放难题
- CI-FSFD 指出"随机切分高估泛化"——这和我们说的 contamination 是同一类病：
 **评测设计不当会系统性地高估能力**
- 企业审计赛道的**验证器是可计算的**（三表勾稽、凭证链断裂、Beneish M-score 红旗），
 比审计师赛道的 rubric 硬，比国家审计的法条匹配软 → 难度居中

## 5. 平行赛道：国家审计（政府审计）

**这一赛道目前没有公开 benchmark，是空白，也是机会。**

已确认的行业动向（审计署及地方审计机关，2026）：

| 信号 | 内容 |
| --- | --- |
| 审计署课题 | 2026-06 将**"人工智能技术在资源环境审计中的应用研究"**列入重点科研方向 |
| 中国审计学会专题 | **"人工智能时代的审计（2026）"**专题研讨会，收到论文 **596 篇**，入选 **35 篇** |
| 入选论文主题 | 生成式 AI 嵌入数据式审计 / 专家系统与大模型协同 / **AI 审计证据的可靠性与证明力** / 国有企业重大风险识别 / 国家审计中 AI 伦理冲突治理 / AI 赋能审计数据治理 |
| 地方实践 | 广西"自然资源资产离任审计智能体"（遥感+政策+推理，自动生成审计疑点和证据链）；山东"天眼""智脑"平台（地理信息一张图 + 文本分析） |
| 省级规划 | 浙江 2026 实施**"智能审计工程"**（夯实数据根基、深化场景赋能）；山东"加快审计智能体升级" |

**为什么这是机会**：
- 有明确的**甲方**（审计署/厅）和**政策驱动**（"十五五"、智能审计工程）
- 有公开的**权威数据源**：审计署《审计结果公告》、移送违纪违法问题线索、部门预算决算公开、地方政府债务数据
- 有**硬判据**：法规条款 + 资金流向勾稽（总额对不上必然有问题）
- **没有任何公开 benchmark** → 这块地是空的

**风险**：数据敏感、口径不一、需要领域专家。建议走 FinancialAuditBench 的路子
（差分隐私先验 + 合成账套），不要试图直接爬真实数据做公开数据集。

## 7. 我们应该讲的三句话（对外叙事）

1. **"公开的 benchmark 一发布就开始腐烂。"**
 证据：EVMbench 无污染重测（-22 例 cutoff 后真实事故）没有 Agent 能端到端利用。

2. **"所以我们造的不是一份数据集，是一台能一直出新鲜考卷的机器。"**
 差分验证保证答案正确，程序化注入漏洞保证题目无限，AI Filter 保证题目够难。

3. **"机器不只服务合约审计——同样的四个零件，可以装在国家审计、企业审计、审计师三条赛道上。"**
 判断标准只有一个：这个赛道有没有能自动跑的验证器。有就能做。
